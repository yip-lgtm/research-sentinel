# 報告契約 (REPORT CONTRACT) — 人性化練習哨兵

這份文件定義「什麼叫做一份合格的科研報告」。品質閘 `quality_gate.py` 依此執行。

## 1. 定位：內部知識庫 vs 對外交付

本哨兵有兩層工作，必須分清楚：

- **內部層（知識庫）**：`knowledge/sections/*.md` 的章節填充、來源 JSON、覆蓋率追蹤。
  這是基建，是手段。**基建進度本身不是報告，永遠不作為報告主題。**
- **交付層（報告）**：每小時投遞給用戶的內容。必須是一份**獨立成立的科研報告**：
  有明確問題、可追溯發現、對人類福祉的意義、可信度評估。
  即使某份報告的素材來自知識庫章節，敘事視角必須是「我們發現了什麼、為何重要」，
  而不是「我們填了哪些章節」。

## 2. 固定五段（不可增刪、不可換序）

1. 主題 / Topic
2. 核心發現 / Key Findings
3. 潛在影響 / Potential Impact
4. 來源依據 / Sources
5. 簡評 / Commentary

每段中文後緊接對應英文段。中文總量 100–1000 字，英文等量，全文 ≤ 9000 bytes。

## 3. 題材門檻

報告必須對下列任一有實質意義：工程、產業鏈、公共福祉、成本、安全、健康、環境、基礎科學應用。
工程教育路徑本身可以是研究對象（例如工程師供給 → 能源／醫療／基建能力），
但必須寫成「發現與影響」，不能寫成「課程體系描述」或「建設進度」。

## 4. 事實與推論分離

- 事實：直接寫，並在來源依據列出機構、標題、日期、完整 URL。
- 推論：必須以【推論】開頭，並在簡評說明其依賴哪些假設。

## 5. 證據標準

- 至少 2 個獨立來源。
- 優先：官方機構／認證機構／政府文件、大學官方頁與公開課程大綱、同行評審期刊、國際組織報告。
- 避免：內容農場、無署名部落格、AI 摘要站、單獨引 Wikipedia。
- 來源被封或超時 → 換來源，不重試；全失敗 → 如實標註缺口，不補猜測。

## 6. 品質閘

`quality_gate.py` 自動判定。FAIL 項目必須修好才可交付。交付前跑一次，exit 0 為準。
