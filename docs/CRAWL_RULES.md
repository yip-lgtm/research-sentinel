# 爬取規則（所有研究 subagent 必讀）

## 目標
建立「工程教育路徑」知識庫的可追溯、可驗證內容。權威來源優先於二手整理。

## 來源優先級（從高到低）
1. 官方機構 / 認證機構 / 政府部門原始頁面（ABET、Engineering Council、HKIE、ICE、NCEES、HKCAAVQ、UGC、HKEAA、QAA、EUR-ACE、教育部/學信網、Washington Accord）
2. 大學官方課程頁與公開課程大綱（representative institutions）
3. 同行評審期刊 / 大學出版社
4. 國際組織報告（UNESCO、OECD、IEEE、ACM、ASEE）
5. 高信譽媒體（僅當有原始文件佐證；必須交叉驗證）

**避免**：內容農場、無署名部落格、AI 生成摘要站、Wikipedia 作為唯一來源（可作導引但須回到原始來源）。

## 每條來源必須記錄
- 機構 / 作者
- 頁面或文件標題
- 發布日期或最後更新日期（查不到就寫「日期未標示」）
- 完整 URL
- 支撐了哪一個具體事實（一句話）

## 事實與推論分離
- 【事實】= 來源直接陳述，可查證
- 【推論】= 由多條事實綜合出的判斷，必須標明「推論」
- 【缺口】= 查不到 / 來源衝突 / 時間不足 → 明確寫出，不要用猜測填補

## 衝突處理
不同來源數字/規則衝突時：兩者都寫出、說明差異可能原因、指出哪個較權威。不要單選一個靜默採用。

## 輸出格式
- 寫入指定路徑的 markdown 檔（繁體中文為主，技術術語保留英文原文）
- 大量使用表格（課程結構、認證層級、學制對照）
- 每節末尾附「本節缺口」清單
- 字數目標 2000–3500 字（每個任務），寧可精確不要灌水

## 同時輸出 JSON
寫入指定路徑的 JSON 檔，格式：
```json
{
  "section": "01",
  "title": "中學／高中工程基礎與升學銜接",
  "sources": [
    {"org": "機構", "title": "標題", "date": "YYYY-MM-DD 或 未標示", "url": "https://...", "supports": "支撐的事實一句話"}
  ],
  "gaps": ["缺口描述"],
  "subtopics_covered": ["已覆蓋子項"],
  "subtopics_missing": ["未能覆蓋子項"]
}
```
JSON 必須合法（能被 python json.load 讀取）。

## 紀律
- 每個數字、每條規則都要有來源。沒有來源的內容一律刪除，不要「一般來說」「通常」這類模糊表述。
- 引用機構自己發布的頁面時，也要註明該頁面版本/年份（例如 ABET 2025-2026 criteria）。
- 時間不足時寧可少寫一節，也不要留下未驗證的內容。
